# SKILL.md 骨架

放在项目的 `.claude/skills/<名字>/SKILL.md`，只对这个项目生效；放在用户目录的 `~/.claude/skills/<名字>/SKILL.md`，所有项目都能用。文件夹名和 name 保持一致。

## description 怎么写

智能体靠 description 判断现在该不该用这个 skill。写什么情况下用，最好再写一句什么时候不用。

写成了标题（不好）：

```
description: DID 检查清单
```

写成了触发条件（好）：

```
description: 当用户要评估一项政策的效果、做双重差分或事件研究时使用。先核对每个处理单位的起始时间和出处，再估计。不用于横截面回归或描述统计。
```

## 骨架

下面的内容复制到你的 SKILL.md，方括号换成你自己的。

```
---
name: [did-checklist]
description: [当用户要……时使用。先……。不用于……。]
---

# [名字]

## 什么时候用

[一两句话，和 description 一致，可以多写几个例子。]

## 步骤

1. [第一步，例如：读 reports/treatment_timing.csv；没有这个文件就停下来，请用户先建]
2. [第二步]
3. [第三步]

## 停下来问人

- [例如：处理时间找不到原文出处时]
- [例如：对照组里有后来也被处理的单位时]
- [例如：容差需要确认时]

## 规则（来自之前犯过的错误）

- [例如：不要把所有单位的处理时间统一设成全国文件的年份]
- [例如：处理前系数不显著，不要写成“平行趋势成立”]

## 产出

- [文件名和位置，例如 reports/event_study_coefs.csv]
- [例如 reports/figures/event_study.png]

## 怎样算完成

- [例如：DECISIONS.md 里记录了对照组定义和看图标准]
- [例如：审稿意见逐条有回应]
```

## 写完以后

1. 开一个新会话，不提 skill 的名字，说一句应该触发的话。
2. 再说一句不该触发的话。
3. 没有调用：多半是 description 写得不对。调用了但跳过某一步：把那一步写得更明确。
