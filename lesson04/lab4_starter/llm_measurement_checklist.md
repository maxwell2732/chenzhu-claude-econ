# 用大模型构造变量：检查清单

用大模型给文本打分、分类或者模拟受访者，构造新的变量时，对照这份清单。内容参考 Jha（2026），AI for Finance Research，例子改为经济学场景。

## 审稿人会问的八个问题

1. **用了哪个模型？** 写明具体版本和使用日期。最好用开源权重或带时间戳、可以固定的版本。
2. **提示是什么？** 完整提示放附录；说明提示是怎样定下来的；换一种提示，结果变不变。
3. **有没有前视偏差？** 模型训练时是否已经见过你要预测的结果或那段时期的信息。
4. **怎样验证？** 和人工标注、调查结果或已知基准比较，报告一致率。
5. **比什么好？** 和词典法、简单控制变量的基准模型比较，大模型多带来了什么。
6. **测的是什么？** 确认它测的是你说的那个概念，而不是文本的语气、长度或者主体规模。
7. **能不能复现？** 记录温度、版本和代码；明年用同样的调用能否得到同样的结果。
8. **经济含义在哪里？** 除了统计显著，说明量级，以及它回答了一个大家关心的问题。

## 前视偏差的处理办法

| 办法 | 做法 |
| --- | --- |
| 训练截止日之后评估 | 只用模型训练截止日之后的数据检验预测能力 |
| 去掉识别信息 | 删去公司名、地名、日期，让模型无法回忆具体事件 |
| 衡量信息损失 | 比较去识别前后的结果，评估去掉了多少有用信息 |
| 直接检验 | 用专门的设计检验是否用到了之后才可能知道的信息 |
| 预测未公开的目标 | 例如保密的调查答复 |
| 固定模型版本 | 用开源权重或带时间戳的版本 |

## 六步验证

1. **定义**：看结果之前，写出概念和带具体锚点的评分标准。
2. **人工标注**：随机抽一批样本自己标注；提示只在这批样本上调整。
3. **比较**：模型和人工的一致率；和外部基准的相关性。
4. **看分布**：画出分数分布；大量集中在少数几个值上，说明评分映射有问题。
5. **压力测试**：换提示措辞、换模型、换示例顺序，报告哪些结论会变。
6. **比方法**：在经济学检验里和词典法、简单控制变量的模型比较。

这些选择要像双重差分设计的关键设定一样，详细记录、充分说明。

## 成本

- 大规模调用用 API 脚本，不要在一个对话或 Claude Code 会话里逐条处理。API 按调用量另外计费，不在聊天订阅里。
- 先用小模型，抽 200 个左右的结果和手工标注比较，达不到要求再换更强的模型。
- 先试跑 20 条，逐条核对，再跑全部。
