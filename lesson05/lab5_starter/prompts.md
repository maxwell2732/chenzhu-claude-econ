# 第 5 课提示

方括号里的内容换成你自己的。

## 一、复制包路线

### 1. 加固复制包

```
我要把这个项目整理成别人能重跑的复制包。先不要改代码，先告诉我：
1）从原始数据到每张表、每个图，现在要按什么顺序运行哪些脚本；
2）哪些数字是手打进报告或正文的；
3）哪些地方用了随机数但没有设种子；
4）哪些路径写死了我电脑上的位置。
然后起草 run_all.sh，等我确认后再改脚本。
```

### 2. 新会话审查（没有 analysis_plan.md 时用）

开一个新会话：

```
你是一位只读的审查人。读 scripts/、logs/、output/ 和 reports/，不要运行代码，不要改文件。
检查：识别策略和结论是否匹配；脚本里的设定和报告里写的是否一致；
报告里的每个关键数字能否在日志里找到。
按严重程度列出问题，最后给出裁决：
APPROVE（没有严重或主要问题）、REQUEST_CHANGES（有主要问题）、
BLOCK（有严重问题，或识别撑不住因果结论，或结果在日志里找不到）。
写进 reports/review_report.md。
```

## 二、写作（按我的写作顺序）

顺序：分析完成 → 1 数据与方法 → 2 定主题 → 3 文献综述 → 4 定贡献 → 5 定题目 → 6 列大纲 → 7 确认大纲 → 8 一章一章写。
第 2、4、5、7 步由你决定，不交给它。论文稿放在 `paper/` 下，每一章一个文件。

### W1. 起草数据与方法（第 1 步）

```
根据 scripts/、logs/、reports/ 和 codebook，起草论文的数据与方法部分，写进 paper/02_data_methods.md：
数据来源；样本筛选的每一步及样本量；变量定义；估计方程和识别假设。
数字只用 output/numbers.json 里的，不要自己算；不写结果和结论。
写不清楚的地方标【待确认】，不要猜。
```

写完跑：`python ~/lab5_starter/check_numbers.py paper/02_data_methods.md output/numbers.json`

理论机制路线：把“数据与方法”换成“模型设定”，依据 `outputs/model_primitives.md`。

### W2. 文献综述（第 3 步）

```
我的研究问题是：【一句话】。请做文献综述，写进 paper/lit_review_notes.md：
按研究问题和方法把文献归类，每一类说清楚已有发现和还没解决的问题。
每条文献给出作者、年份、题目、期刊和 DOI 或可访问的链接。
找不到出处的不要列，不确定的标【待核对】。不要编造文献。
```

拿到后逐条核对：文献存在，而且确实说了它说的那个意思。

### W3. 定贡献和题目（第 4、5 步，你自己写）

在 `paper/contribution.md` 里自己写三句话：

```
我们发现了什么：
文献里缺什么：
我们补上了什么：
暂定题目：
```

可以让它挑毛病，但不要让它替你写：

```
读 paper/contribution.md、paper/lit_review_notes.md 和 output/ 里的主要结果。
只指出问题：贡献是否超出了结果能支持的范围；文献缺口是否真的存在；题目和贡献是否一致。不要改写。
```

### W4. 列大纲（第 6 步）

```
根据 paper/contribution.md 和 output/ 里的表图，列出论文大纲，写进 paper/outline.md：
每一节要回答的问题、用到的表图、大致篇幅。先不要写正文，等我确认。
```

你改到满意，在 outline.md 开头写上“已确认”和日期。

### W5. 一章一章写（第 8 步）

每一章用一次：

```
读 paper/outline.md（已确认）和已经定稿的章节【列出文件】。
只写【第 X 节：名称】，写进 paper/0X_名称.md。
数字只用 output/numbers.json 里的；引用只用 lit_review_notes.md 里核对过的文献。
写完停下，不要接着写下一节。
```

这一节你审改、跑 check_numbers.py、`git commit` 以后，再写下一节。

### W6. 当编辑，不重写

```
逐段读下面这一节。只标出问题，不要改写：
哪里说得不清楚，哪里术语前后不一致，哪里的说法比证据强。
每个问题给出原文位置和理由。数字和引文不要动。
```

### W7. 新会话审稿

```
你是一位怀疑识别策略的计量经济学家，正在审这篇投给【期刊】的稿子。
列出至少五个主要问题，按严重程度排序，每个问题指出原文位置。
不要评价写作风格，不要客套。
```

## 三、理论机制路线

### T1. 新会话检查推导

开一个新会话，只给 `outputs/model_primitives.md` 和 `outputs/proof_sketches.md`，不说这是你的模型：

```
下面是一个理论模型的设定和证明草图。逐步检查推导：
每一步用了哪个假设，有没有跳步或者隐含的假设。
对每个命题，尝试构造一个反例。
最后说明：哪些结论只依赖一般性假设，哪些依赖特定的函数形式。
先列问题，不要改写。
```

### T2. 函数形式检查

在 pAI-Econ 的会话里：

```
对每个假说列一张表：依赖哪些假设；如果把【某个函数形式】换成更一般的形式，
结论是否还成立。不确定的写“不确定”，不要猜。
```
