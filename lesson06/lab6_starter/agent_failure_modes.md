# 智能体常见的八种错误：自查表

前两列整理自 Jha, Manish. *AI for Finance Research*. Georgia State University, 2026。第三列是本课加的，对应前五课里讲过的应对办法。

用法：做完一个项目，或者换了一个工具（Codex、Trae、WorkBuddy 等）以后，逐行问自己：这种错误在我的工作流里有没有发生的机会？如果有，我用什么办法发现它？

| 错误 | 在研究中的表现 | 前五课的应对 | 我的工作流里怎么防 |
| --- | --- | --- | --- |
| 编造 | 不存在的变量名、文献、命令选项 | 第 3 课：项目 CLAUDE.md 写明真实变量名；第 1 课：用独立来源核对一个数字 | |
| 偷懒 | 跳过步骤，把没做完的说成做完了 | 第 4 课：事先锁定容差，PARTIAL 如实报告；第 5 课：全新克隆重跑 | |
| 只看说明，不看数据 | 按问卷或印象描述数据，不去读文件 | 第 3 课：先审查，再清理；每一轮报告非缺失值个数 | |
| 范围蔓延 | 顺手改了没让它改的代码或数据 | 第 1 课：git diff；第 3 课：deny 规则和哈希校验 | |
| 长会话质量下降 | 忘记前面的约定，前后不一致 | 第 1 课：把进度写进 progress.md，开新会话 | |
| 自信的领域错误 | 聚类层级、TWFE 用法等专业判断出错 | 第 4 课：识别由人判断；用新会话审代码 | |
| 悄悄做数据决定 | 删样本、改合并方式而不说明 | 第 3 课：每次合并都有报告，决定记进 DECISIONS.md | |
| 规则文件膨胀 | CLAUDE.md 越写越长，规则互相冲突 | 第 5 课：规则文件写短，每月清理一次 | |

模型变强以后，这些错误会少一些，但不会消失，而且更不容易被发现。
